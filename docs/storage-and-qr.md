# 저장 구조와 신발 ID (QR)

## 저장 구조
```
captures/<카메라>/<id>.jpg  <id>.json     카메라별 폴더: top/, front/, back/ ... (이미지 + 그 카메라의 정보)
captures/.sets/<id>.json                 세트(한 순간) 전체 정보와 라벨 (앱이 읽는 원본, 숨김 폴더)
captures/.thumbs/<카메라>/<id>.jpg  .background.jpg  .settings.json
exports/shoe_<시각>/{images,labels}/{train,val}/  data.yaml  manifest.json   + shoe_<시각>.zip
```
기준 카메라가 캡처 조건을 만족하면 연결된 모든 카메라에서 같은 순간의 프레임을 하나씩 저장하며, 같은 `<id>`를 씁니다.

**신발 ID (QR 값)**: `<id>`는 `<QR값>_<캡처 시각>`입니다. 예: `SHOE-1234_20261008_090135_293`. 신발 한 번이 지나가며 찍힌 전·중·후 컷은 **한 묶음으로 저장**하고, 묶음 안의 모든 카메라·모든 컷 사진에서 QR을 먼저 읽어 가장 많이 읽힌 값을 **묶음 전체의 파일명 앞**에 붙입니다. 그래서 QR이 한 장에서만 읽혀도 같은 신발의 모든 사진이 같은 접두어를 갖습니다.
- **QR을 찾는 순서** (찾으면 거기서 멈춥니다):
  1. 저장할 사진(묶음의 모든 컷, QR 카메라)에서 읽기 → `shoe_id_source: capture`
  2. 신발이 지나가는 동안 실시간 스캔이 읽은 값 → `live`
  3. 저장할 사진을 **타일로 나눠 확대해서 다시 읽기**(작은 QR용, 사진 한 장에 0.3~0.8초 더 걸림) → `capture_zoom`
  4. 캡처 뒤 몇 초 동안 실시간 스캔이 읽은 값을 기다림 → `live_late`

  모두 실패하면 접두어 없이 시각만 씁니다(예: `20261008_090135_293`).
- **저장이 늦어질 수 있습니다.** QR을 못 읽은 자동 캡처 묶음은 4단계에서 최대 `ON_QR_WAIT_SEC`(기본 4초) 더 기다린 뒤 저장합니다. 저장 작업자가 3개라서 한 묶음이 기다리는 동안에도 다음 신발은 바로 저장됩니다. 수동 캡처는 기다리지 않습니다. 파일은 이름이 정해진 뒤에 한 번에 쓰므로 이름이 바뀌는 일은 없습니다.
- 실시간 스캔 값으로 인정하는 시간대는 그 신발의 **첫 컷 `ON_QR_LIVE_WINDOW_SEC`(기본 3초) 전부터 마지막 컷 `ON_QR_WAIT_SEC` 뒤까지**입니다. 이 구간에서 가장 많이 읽힌 값을 쓰고, 같으면 가장 최근 값입니다. `ON_QR_ZOOM=0`이면 3단계를 건너뜁니다.
- 파일명에는 영문자·숫자·`.`·`_`·`-`만 쓰고 나머지 문자는 `-`로 바꿉니다(최대 40자, 한글은 파일명에서 빠짐). **읽은 원본 값은 JSON의 `shoe_id`에 그대로** 있고, `shoe_id_source`는 위 네 가지(`capture`, `live`, `capture_zoom`, `live_late`) 중 하나입니다. 한 묶음에서 서로 다른 QR이 읽히면(신발 두 개가 보일 때) 아래 "이웃 신발 구분"으로 하나를 고르고 나머지는 `shoe_id_other`에 남깁니다.
- 실시간 스캔 값(`live`, `live_late`)은 앞뒤 신발의 값일 수도 있습니다. 사진에서 읽은 값(`capture`, `capture_zoom`)이 더 믿을 만합니다.

### 이웃 신발 구분 (신발이 붙어서 올 때)
벨트에 신발이 가깝게 올라오면 옆 카메라 사진 가장자리에 앞뒤 신발과 그 QR 라벨이 같이 보일 수 있습니다. 자동 캡처는 **가운데 컷을 찍는 순간 저장 대상 신발이 사진 한가운데에 있다**는 점을 이용해 구분합니다(수동 캡처는 해당 없음).
- QR의 가로 위치가 사진 가운데에 가까울수록 많이 셉니다. 가운데는 1, `ON_QR_CENTER_BAND`(기본 0.4, 사진 폭 대비)만큼 떨어지면 0이고, 그보다 바깥의 코드는 이웃 신발의 것으로 보고 무시합니다. 가장 많이 읽은 값이 아니라 **점수 합이 가장 큰 값**이 이 신발의 ID가 됩니다.
- 실시간 스캔은 읽을 때의 프레임 시각과 QR 위치를 함께 기록하고, 가운데 컷 시각 전후 `ON_QR_MATCH_SEC`(기본 1초) 안의 읽기만 같은 방식으로 셉니다. 그래서 앞뒤 신발이 지나가는 때의 읽기는 들어오지 않고, 못 읽은 신발의 저장도 `ON_QR_WAIT_SEC`보다 빨리(최대 이 시간 + 0.5초) 끝납니다.
- 가운데 근처에서 읽은 코드가 없고 가장자리 코드만 있으면 **ID를 붙이지 않고**(`ID 없음`) 가장자리 값을 `shoe_id_other`에 남깁니다. 틀린 ID가 붙는 것보다 비워 두는 쪽이 안전하기 때문입니다.
- 한 캡처에서 서로 다른 값이 읽히면 `logs/collect.log`에 `QR_CONFLICT`(알림은 가지 않음)가 남고, `capture.log`에는 `other_codes=`로 나옵니다. 이 줄이 자주 보이면 신발 간격이나 `ON_QR_CENTER_BAND`를 확인하세요.
- `ON_QR_CENTER_BAND=0`이면 이 기능을 끄고 예전처럼 동작합니다(모든 코드를 세고, 실시간 읽기는 `ON_QR_LIVE_WINDOW_SEC` ~ `ON_QR_WAIT_SEC` 구간).
- 조정: 사진에서 QR이 자주 가장자리에서만 읽히면(신발이 중앙에서 많이 벗어나 찍힘) 값을 키우고(0.45), 이웃 신발 QR이 섞이면 줄이세요(0.3). 신발 가운데에서 한쪽 끝까지가 사진 폭의 절반을 넘지 않는 크기여야 합니다.
- **QR 검색 영역(`ON_QR_ROI`)**: `x,y,w,h`(화면 대비 비율, 예 `0,0.45,1,0.4` = 높이 45~85% 띠)로 정하면 실시간 스캔은 그 영역만, 저장된 사진은 그 영역을 먼저(원본과 2배 확대) 찾고 못 찾으면 전체를 찾습니다. 비우면 전체입니다. 좌표는 줌한 화면 기준입니다. 영역을 좁히면 빨라지지만, 스티커가 영역 밖(예: 신발 목)에 붙으면 실시간 스캔은 못 읽습니다(저장된 사진은 전체 검색이 받아 줌).
- **QR 크기 진단**: 읽은 코드는 사진에서의 한 변 길이 `size_px`가 JSON `qr`에 남습니다. 위치는 찾았지만 읽지 못하면 `views.<카메라>.qr_seen_px`에 그 크기가 남고, `capture.log`의 `qr_px=right:58(not-read)`, QR 페이지의 `QR located, not readable 58px` 칩으로 보입니다. 25~29칸 코드는 약 100~120px 이상(모듈당 4px)이어야 읽히니, 이 값으로 노출·해상도·줌 조정이 충분한지 판단하세요. 아무것도 못 찾았을 때는 `qr_px=-`입니다(너무 흐리거나 작아서 위치도 못 찾음).
- **어느 카메라에서 읽을지**: `ON_QR_CAMERAS`(기본 `left,right`)에 적은 카메라에서만 QR을 찾습니다. 실시간 스캔과 저장된 사진 읽기 모두 해당됩니다. 비우면 모든 카메라를 읽고, 카메라 이름을 잘못 적어 하나도 맞지 않으면 설정을 무시하고 전부 읽습니다(스캔이 실수로 꺼지지 않도록).
- **얼마나 자주 읽을지**: `ON_QR_SCAN_HZ`(`.env` 예시 5~15)는 **카메라 한 대당** 초당 실시간 스캔 횟수입니다. 카메라마다 별도 스레드로 돌고, 이미 스캔한 프레임은 다시 스캔하지 않으므로 카메라 fps보다 높여도 소용없습니다. 스캔 한 번은 CPU 코어 하나의 약 0.06~0.1초를 쓰니, 2대에서 5회면 코어 1개 안팎이고 15회면 2~3개입니다. 지나가는 동안 읽을 기회가 늘어나는 만큼 2단계와 4단계의 성공률이 오릅니다.
- 데이터 내보내기 파일명에도 QR 접두어가 그대로 붙습니다. 이미 저장된 샘플의 이름은 바뀌지 않습니다.
`captures/.sets/<id>.json`에는 검출 정보, 카메라 설정, `bbox`(정규화 x,y,w,h / source / reviewed), `label`이 들어 있습니다. `bbox`와 데이터 내보내기는 기준 카메라(`primary_view`) 이미지 기준입니다.
카메라 폴더의 `<id>.json`은 그 카메라의 크기·노출·캡처 시각 차이·QR과 세트의 `label`을 담고, 기준 카메라 쪽에만 `bbox`/`detection`이 들어갑니다. 라벨이나 bbox를 고치면 함께 갱신됩니다(원본은 `captures/.sets/<id>.json`).
자동 캡처는 앱을 시작할 때 **ON**입니다(`.env`의 `ON_AUTO_CAPTURE=0`이면 OFF로 시작해서 실시간 화면의 `자동 캡처` 버튼으로 켭니다). 디스크가 이미 한도를 넘었으면 OFF로 시작합니다.
이전 버전에서 `captures/` 바로 아래에 저장한 `<id>.json`은 앱을 시작할 때 `.sets/`로 자동으로 옮겨지고, 같은 위치의 `<id>.jpg`, `<id>__<카메라>.jpg`는 그대로 읽힙니다.

### 못 읽은 QR 다시 읽기 (`ON_QR_ENHANCE`)
QR 위치는 찾았는데 값을 못 읽는 경우(번짐, 반사, 기울어진 라벨)를 위해, 기본 읽기가 실패한 사진에만 아래를 순서대로 더 시도합니다([backend/qr/enhance.py](../backend/qr/enhance.py)).
1. **위치 주변만 잘라서** 정사각형으로 펴고(원근 보정) 2~4배 확대한 뒤 여러 버전으로 다시 읽기: 그대로, 선명하게(unsharp), **가로 번짐 보정**(컨베이어가 가로로 움직여서 생기는 번짐을 Wiener 필터로 되돌림, 번짐 길이 4·6·9·12px), 대비 보정, 이진화, 밝게/어둡게(반사).
2. 각 버전을 OpenCV 뒤에 **zxing-cpp**로도 읽기(`ON_QR_ZXING`). 흐림과 기울어짐에 OpenCV보다 강합니다. 패키지가 없으면 한 번 안내 문구만 찍고 OpenCV만으로 동작합니다.
3. 위치조차 못 찾은 저장 사진은 zxing-cpp가 사진 전체(그리고 번짐 보정 후)에서 직접 찾기. 번짐 길이를 4가지만 시도하므로 효과는 제한적입니다.
- **zxing 우선 읽기 (먼저 시도)**: OpenCV가 위치를 찾을 수 있는 코드는, 기본 OpenCV 읽기(여러 크기, 대비 보정)보다 **먼저** 잘라서 펴서(rect) zxing-cpp로 읽어 봅니다(최대 0.15초). 신발 옆면의 곡면에 붙은 라벨은 기울고 약간 찌그러져서 OpenCV가 못 읽는 일이 많은데 zxing은 읽습니다. 못 읽으면 예전처럼 OpenCV 읽기와 아래 추가 시도로 이어집니다. 프레임을 고를 때의 QR 읽기 시도(`ON_PICK_QR_TRIES`)와 실시간 스캔도 이 방식을 씁니다. 시험(같은 사진 81장): 읽던 것은 하나도 놓치지 않았고, 기본 읽기로 읽힌 사진이 `10-20 Sample` 24장 중 2장에서 7장으로, `10-23 LEFT3`에서 0/3에서 2/3으로 늘었습니다. 대신 코드가 없는 사진은 위치 찾기(약 0.1~0.2초) 때문에 기본 읽기가 사진당 약 0.2초 더 걸립니다.
- **시간**: 읽힌 사진에는 추가 시간이 없습니다. 못 읽은 사진은 `ON_QR_ENHANCE_SEC`(기본 0.8초)까지만 더 시도하고, 실시간 스캔은 그중 0.25초까지입니다(위치를 찾은 경우에만, 4번 중 1번). 한 번의 캡처에서 한 사진이 값을 읽으면 나머지 컷은 이 추가 시도를 건너뜁니다.
- **어느 방법으로 읽었는지**: 읽은 코드마다 `method`가 JSON(`qr[].method`)에 남습니다. `cv`=기본 방식, `rect`=잘라서 편 사진, `crop`=잘라서 확대만, `:wiener9`=번짐 보정(9px), `:unsharp`, `:adaptive` 등, 끝의 `+zxing`=zxing-cpp가 읽음. QR 화면의 "How the saved pictures were read" 줄에 개수가 나옵니다.
- **효과 확인**: 저장된 사진 폴더(복사본)에서 `.venv/bin/python -m backend.cli.qr_bench <폴더>`로 기본 / 추가 시도 / +zxing를 같은 사진에 돌려 읽힌 개수와 사진당 시간, 새로 읽힌 사진 목록을 비교합니다(`--expect 값`, `--roi x,y,w,h`).
- **되돌리기**: `.env`에 `ON_QR_ENHANCE=0`을 넣고 앱을 재시작하면 이 기능을 쓰지 않고 이전과 똑같이 읽습니다(시험으로 확인: 같은 사진 36장 x 3가지 설정에서 읽은 값/위치/크기 동일). zxing만 끄려면 `ON_QR_ZXING=0`. 코드를 되돌리려면 이 기능의 커밋을 `git revert`하면 됩니다.
- **설치**: zxing-cpp는 `requirements.txt`에 있습니다. Mac에서 한 번 `.venv/bin/python -m pip install zxing-cpp==3.1.1`(또는 `pip install -r requirements.txt`)을 실행하세요.
- **한계**: 크기가 너무 작거나(대략 70px 미만) 번짐이 칸 몇 개 폭을 넘으면(가로 번짐 약 12px 이상) 읽지 못합니다. 이 경우 해결책은 카메라 쪽(초점, 노출, 해상도)입니다.
