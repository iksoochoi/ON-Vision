# 캡처 백업 (`./bin/capture_backup.sh`)

하루가 끝날 때 그날의 캡처를 **통계 정보와 함께 zip 하나로 묶고, 묶은 파일을 `captures/`에서 지워** 디스크를 비웁니다.

## 사용법
```bash
./bin/capture_backup.sh                      # 오늘 것. 오늘 23:59가 될 때까지 기다렸다가 시작 (그냥 켜 두세요, Ctrl+C로 취소)
./bin/capture_backup.sh --now                # 오늘 것을 지금 바로
./bin/capture_backup.sh --date 2026-10-15    # 그 날짜 것 (지난 날짜는 바로 시작)
./bin/capture_backup.sh --dry-run            # 무엇을 할지만 보여 주고 아무것도 바꾸지 않음
./bin/capture_backup.sh --keep               # zip은 만들되 captures의 파일은 지우지 않음
./bin/capture_backup.sh --at 23:30 --out /Volumes/Backup   # 시작 시각과 zip 폴더 바꾸기
```
- 처음 한 번 `chmod +x bin/capture_backup.sh`가 필요할 수 있습니다.
- 기다리는 동안 Mac이 잠들지 않도록 `caffeinate`를 함께 씁니다(화면은 꺼져도 됩니다). 터미널을 닫으면 멈추니 `tmux`나 `nohup ./bin/capture_backup.sh &`로 두거나, 터미널 창을 열어 둔 채로 두세요.
- 이미 23:59가 지났으면 "지났으니 바로 시작합니다"라고 알리고 바로 시작합니다.
- 출력은 화면과 `logs/backup.log`에 남습니다.
- zip 위치는 `.env`의 **`ON_BACKUP_DIR`**(기본 프로젝트의 `backups/`)입니다. 하루치가 수십 GB가 될 수 있으니 **여유 있는 디스크**를 지정하세요.

## 순서 (어느 단계에서든 문제가 생기면 거기서 멈추고, 아무것도 지우지 않습니다)
1. 그날 23:59까지 기다립니다.
2. 그날의 세트를 찾습니다. 세트의 날짜는 첫 컷의 촬영 시각 기준이라, 자정을 걸친 한 세트는 쪼개지지 않습니다. **방금(60초 안에) 저장된 세트는 아직 쓰는 중일 수 있어 이번에는 빼고** 다음에 백업합니다.
3. `captures/readme.md`에 **통계 정보**를 씁니다(아래).
4. 세트의 파일(사진, 썸네일, 카메라별 JSON, 세트 JSON)과 `readme.md`를 **`capture_<날짜>.zip`** 으로 묶습니다. 사진은 이미 JPEG라 압축하지 않고 담기만 해서 빠릅니다. 같은 이름이 있으면 덮어쓰지 않고 `capture_<날짜>_2.zip`으로 만듭니다. 디스크 여유가 부족하면 시작도 하지 않습니다.
5. zip을 **다시 읽어서 확인**합니다(모든 파일의 CRC, 파일 이름과 크기가 묶으려던 것과 같은지).
6. **확인이 끝난 뒤에만** zip에 들어간 파일을 `captures/`에서 지웁니다. `readme.md`는 `captures/`에 남습니다(다음 백업이 새로 씁니다).
- **지우지 않는 것**: 다른 날짜의 세트, `.settings.json`, 배경 사진 등 세트가 아닌 파일, 앱이 방금 저장한 세트.
- 앱은 켜 둔 채로 해도 됩니다. 지워진 파일은 최대 2분 안에 화면(Browse, QR)에서 사라집니다.
- 23:59 이후에 저장된 그날의 세트(자정 전 몇 초)는 남을 수 있습니다. 다음 날 `./bin/capture_backup.sh --now --date <그날>`을 한 번 더 하면 `_2.zip`으로 마저 백업합니다.

## `readme.md`에 쓰이는 내용
zip 맨 위에도 같은 파일이 들어갑니다.
1. **머리말**: 대상 날짜, 만든 시각, **세트 수, 컷 수, 이미지 수, 전체 용량**(사진+썸네일+JSON), 첫/마지막 촬영 시각, 압축 파일 이름, 이번에 제외한 것(방금 저장된 세트 등).
2. **View(카메라)별**: top / back / left / front / right마다 **세트, 컷, 이미지 개수, 사진 용량, 썸네일 용량, JSON 용량, 합계, 사진 한 장 평균 용량**과 합계 줄. 카메라가 끊겨 **사진이 빠진 컷**이 있으면 어느 세트의 어느 View가 왜 빠졌는지 목록.
3. **시간대별**: 시(0~23)마다 세트 수, 이미지 수, 용량, QR 인식 / 미인식 / 인식률.
4. **QR 인식 결과**
   - 세트 중 인식 / 미인식 / **인식률**, 미인식 중 "위치만 찾고 못 읽음"과 "아예 못 찾음", 서로 다른 신발(QR 값) 종류 수
   - **값을 읽은 곳**(저장된 사진 `capture`, 실시간 `live`, 캡처 직후 `live_late`, 확대 `capture_zoom`)
   - **어느 카메라에서 읽었나**(left / right 등)
   - **읽은 방법**(`cv` 기본, `rect+zxing` 등 추가 시도)
   - **QR 크기별**(사진에서 가장 큰 QR의 한 변 px: 읽음 / 위치만 찾고 못 읽음)
   - **라벨 상태** 개수
   - **신발(QR 값)별 세트**: 값, 세트 수, 첫/마지막 촬영, 출처
   - **QR 값이 없는 세트 목록**: 촬영 시각, 세트 id, 위치만 찾은 QR 크기
5. **압축 파일 안의 구성**과 파일 개수. zip 안의 경로가 `captures/` 기준이라 풀어서 그대로 합칠 수 있습니다.

숫자는 QR 화면의 일별 표와 같은 기준(세트 = 신발 한 번 지나감)입니다.

## 복원
```bash
unzip backups/capture_2026-10-15.zip -d captures/    # 풀면 .sets/, top/, back/ ... 이 제자리에 들어갑니다
```
앱은 2분 안에 복원된 세트를 화면에 다시 보여 줍니다.

## 주의
- 지우는 것은 **영구 삭제**입니다(휴지통으로 가지 않음). 처음에는 `--dry-run`으로 계획을 보고, 다음에 `--keep`으로 zip이 잘 만들어지는지 확인한 뒤 지우는 실행을 하세요.
- zip을 다른 디스크나 NAS로 옮겨 두는 것은 이 스크립트가 하지 않습니다.
