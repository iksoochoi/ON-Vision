# 캡처 백업 (`./bin/capture_backup.sh`)

> 불량 탐지 결과(`captures/.predict/<id>.json`)도 세트와 함께 zip에 들어가고, 삭제할 때 같이 지워집니다.

하루가 끝날 때 그날의 캡처를 **통계 정보와 함께 zip 하나로 묶고, 묶은 파일을 `captures/`에서 지워** 디스크를 비웁니다.

## 사용법
```bash
./bin/capture_backup.sh                      # 오늘 것. 오늘 23:59가 될 때까지 기다렸다가 시작 (그냥 켜 두세요, Ctrl+C로 취소)
./bin/capture_backup.sh --now                # 오늘 것을 지금 바로
./bin/capture_backup.sh --date 2026-10-15    # 그 날짜 것 (지난 날짜는 바로 시작)
./bin/capture_backup.sh --all                # 오늘 이전까지 쌓인 모든 날짜를 날짜별 zip으로 차례로 (오래된 날부터). 시작은 오늘 23:59
./bin/capture_backup.sh --dry-run            # 무엇을 할지만 보여 주고 아무것도 바꾸지 않음
./bin/capture_backup.sh --delete --date 2026-10-15   # 백업 없이 그 날짜 데이터만 삭제 (먼저 물어봄)
./bin/capture_backup.sh --delete --all --now         # 백업 없이 오늘까지 쌓인 모든 데이터를 삭제 (먼저 물어봄)
./bin/capture_backup.sh --keep               # zip은 만들되 captures의 파일은 지우지 않음
./bin/capture_backup.sh --at 23:30 --out /Volumes/Backup   # 시작 시각과 zip 폴더 바꾸기
```
- 처음 한 번 `chmod +x bin/capture_backup.sh`가 필요할 수 있습니다.
- 기다리는 동안 Mac이 잠들지 않도록 `caffeinate`를 함께 씁니다(화면은 꺼져도 됩니다). 터미널을 닫으면 멈추니 `tmux`나 `nohup ./bin/capture_backup.sh &`로 두거나, 터미널 창을 열어 둔 채로 두세요.
- 이미 23:59가 지났으면 "지났으니 바로 시작합니다"라고 알리고 바로 시작합니다.
- 출력은 화면과 `logs/backup.log`에 남습니다.
- zip 위치는 `.env`의 **`ON_BACKUP_DIR`**(기본 프로젝트의 `backups/`)입니다. 하루치가 수십 GB가 될 수 있으니 **여유 있는 디스크**를 지정하세요.

## 카메라당 3장 중 1장만 남기기 (`./bin/thin_captures.sh`, 임시 도구)
`ON_PICK_MODE=classic`(전·중·후 3컷)으로 저장된 날짜의 사진을 **카메라마다 1장만** 남기고 나머지 2장을 지웁니다. 며칠치 데이터를 정리하는 용도입니다. 되돌릴 수 없으므로 **백업 zip을 먼저 만들어 두세요**(스크립트가 그 zip을 확인합니다).
```bash
./bin/capture_backup.sh --date 2026-10-17 --keep          # 1. 백업 zip을 만들되 파일은 남김
./bin/thin_captures.sh --date 2026-10-17 --dry-run        # 2. 무엇이 남고 지워질지 보기 (아무것도 안 바꿈)
./bin/thin_captures.sh --date 2026-10-17                  # 3. 실행 (먼저 물어봄. 'thin' 입력, --yes면 안 물음)
./bin/thin_captures.sh --date 2026-10-17 --mode center    # 카메라별 선별 대신 가운데 컷 전체를 남김
./bin/thin_captures.sh --date 2026-10-17 --captures /경로/압축푼/captures   # 압축을 푼 폴더에서 하기
```
- **카메라별로 남길 사진(기본 `--mode best`)**: ① 그 카메라 사진에서 QR 값이 읽힌 컷이 우선, ② 아니면 선명도(저장할 때 잰 값)가 가장 높은 컷. 다만 가운데 컷이 아닌 컷은 가운데 컷보다 **3% 넘게 선명해야** 선택됩니다. ③ 그 외는 가운데 컷.
- **세트는 하나로 합칩니다**: 신발 한 번(한 pass)이 3개 세트(컷)로 저장돼 있었는데, 남긴 5장을 **가운데 컷의 id** 아래 한 세트로 모읍니다(다른 컷에서 고른 사진은 그 id로 옮기고 세트 JSON과 카메라별 JSON을 다시 씁니다). JSON에는 `burst.count 1`, 어느 컷에서 왔는지(`thinned.from`), 가운데 시점에 대한 offset이 남습니다.
- **지워지는 것**: 나머지 두 컷의 사진, 썸네일, JSON(세트 JSON을 가장 먼저), 그리고 그 pass의 **불량 탐지 결과**(`.predict/`: 사진이 바뀌어 맞지 않음). 불량 탐지 워커가 새 결과를 만듭니다(`ON_PREDICT_MAX_AGE_HOURS`보다 오래된 날짜는 `python -m backend.predict.worker --backfill`).
- **건드리지 않는 것**: 다른 날짜, 수동 캡처, **컷이 다 모이지 않은 pass**, 이미 1컷인 pass, 방금(60초 안에) 저장된 세트. 건너뛴 것은 이유와 함께 개수가 나옵니다.
- 앱은 켜 둔 채로 해도 되고(지난 날짜), 화면에는 2분 안에 반영됩니다. 한 pass씩 처리하므로 중간에 멈춰도 끝난 pass는 끝난 상태이고 나머지는 그대로입니다. 출력은 `logs/backup.log`에도 남습니다.
- 시험: 10-20 샘플 데이터(4켤레, 3컷, 5대)의 JSON 구조로 만든 폴더에서 선별 규칙, 사진/JSON/썸네일 이동, 다른 컷과 결과 삭제, 다른 날짜와 미완성 pass 보존, 두 번째 실행 시 할 일 없음, `--mode center`를 확인했습니다(사진 파일은 작은 가짜 파일).

## `--delete` (백업 없이 삭제만)
zip을 만들지 않고 **날짜 기준으로 데이터만 지웁니다.** 되돌릴 수 없으니 먼저 지울 양을 보여 주고 확인을 받습니다.
```bash
./bin/capture_backup.sh --delete --date 2026-10-15 --dry-run   # 무엇이 지워질지만 확인 (아무것도 안 지움)
./bin/capture_backup.sh --delete --date 2026-10-15             # 그 날짜. 지난 날짜면 바로 시작
./bin/capture_backup.sh --delete                               # 오늘 것. 오늘 23:59가 되면 시작
./bin/capture_backup.sh --delete --all --now                   # 전체 삭제: 오늘까지 세트가 있는 모든 날짜
```
- 시작하면 날짜마다 `세트 수, 이미지 수, 용량`과 합계를 보여 주고 **`delete`라고 직접 입력해야** 진행합니다. 다른 말을 입력하면 취소하고(종료 코드 4) 아무것도 지우지 않습니다.
- 터미널이 없는 실행(`nohup`, 예약 등)은 물을 수 없어서 **`--yes`를 붙여야** 합니다. 붙이지 않으면 멈춥니다.
- 시각 규칙은 백업과 같습니다: 기다리는 날짜는 23:59(`--at`, `--now`로 조정), 지난 날짜는 바로.
- 지우는 대상은 백업과 같습니다. **세트의 사진, 썸네일, JSON만** 지우고, `.settings.json`, 배경 사진, `readme.md` 같은 것은 건드리지 않습니다. 방금(60초 안에) 저장된 세트는 남깁니다. `.sets/`의 세트 파일을 **먼저** 지워서 사진만 없는 세트가 목록에 남지 않게 합니다.
- `--keep`과는 함께 쓸 수 없습니다. 결과(날짜별로 지운 개수와 용량)는 `logs/backup.log`에 남습니다.

## `--all` (쌓인 날짜를 한꺼번에)
- `--all`은 세트가 있는 **모든 날짜**를 **오래된 날부터 하나씩** 백업합니다(날짜마다 zip 하나, 아래 순서를 날짜마다 반복). 기본은 **오늘까지**이고, `--date`를 같이 주면 그 날짜까지입니다.
- 예: 10-14부터 쌓여 있는 상태에서 10-16에 `./bin/capture_backup.sh --all`을 실행해 두면, **10-16 23:59에 시작**해서 `capture_2026-10-14.zip`, `capture_2026-10-15.zip`, `capture_2026-10-16.zip`을 차례로 만듭니다. 지난 날짜도 시작 시각까지 기다렸다가 함께 처리합니다(낮에 디스크를 많이 쓰며 캡처를 방해하지 않게 하려는 것입니다). 지금 바로 하려면 `--now`를 붙이세요.
- 시작 시각은 기본 23:59이고 `--at 23:58`처럼 바꿀 수 있습니다.
- 오늘 것은 맨 마지막에 처리되므로, 앞 날짜들이 오래 걸리면 오늘의 백업은 자정을 넘겨서 끝날 수 있습니다(문제는 없습니다. 오늘 날짜의 세트만 담고, 자정 이후에 저장된 것은 다음 날 몫입니다).
- 한 날짜에서 디스크 부족이나 zip 확인 실패(종료 코드 2, 3)가 나면 **거기서 멈추고** 이후 날짜는 그대로 둡니다. 앞서 끝낸 날짜의 zip은 그대로입니다. 디스크는 날짜 하나씩 처리하므로 한 날짜의 zip 용량만큼의 여유만 있으면 됩니다.

## 순서 (어느 단계에서든 문제가 생기면 거기서 멈추고, 아무것도 지우지 않습니다)
1. 그날 23:59까지 기다립니다.
2. 그날의 세트를 찾습니다. 세트의 날짜는 첫 컷의 촬영 시각 기준이라, 자정을 걸친 한 세트는 쪼개지지 않습니다. **방금(60초 안에) 저장된 세트는 아직 쓰는 중일 수 있어 이번에는 빼고** 다음에 백업합니다.
3. `captures/readme.md`에 **통계 정보**를 씁니다(아래).
4. 세트의 파일(사진, 썸네일, 카메라별 JSON, 세트 JSON)과 `readme.md`를 **`capture_<날짜>.zip`** 으로 묶습니다. 사진은 이미 JPEG라 압축하지 않고 담기만 해서 빠릅니다. 같은 이름이 있으면 덮어쓰지 않고 `capture_<날짜>_2.zip`으로 만듭니다. 디스크 여유가 부족하면 시작도 하지 않습니다.
5. zip을 **다시 읽어서 확인**합니다(모든 파일의 CRC, 파일 이름과 크기가 묶으려던 것과 같은지).
6. **확인이 끝난 뒤에만** zip에 들어간 파일을 `captures/`에서 지웁니다. `readme.md`는 `captures/`에 남습니다(다음 백업이 새로 씁니다).
- **지우지 않는 것**: 다른 날짜의 세트, `.settings.json`, 배경 사진 등 세트가 아닌 파일, 앱이 방금 저장한 세트.
- 앱은 켜 둔 채로 해도 됩니다. 지워진 파일은 최대 2분 안에 화면(Gallery, QR)에서 사라집니다.
- 23:59 이후에 저장된 그날의 세트(자정 전 몇 초)는 남을 수 있습니다. 다음 날 `./bin/capture_backup.sh --now --date <그날>`을 한 번 더 하면 `_2.zip`으로 마저 백업합니다.

## `readme.md`에 쓰이는 내용
zip 맨 위에도 같은 파일이 들어갑니다.
1. **머리말**: 대상 날짜, 만든 시각, **세트 수, 컷 수, 이미지 수, 전체 용량**(사진+썸네일+JSON), 첫/마지막 촬영 시각, 압축 파일 이름, 이번에 제외한 것(방금 저장된 세트 등).
2. **View(카메라)별**: top / back / left / front / right마다 **세트, 컷, 이미지 개수, 사진 용량, 썸네일 용량, JSON 용량, 합계, 사진 한 장 평균 용량**과 합계 줄. 카메라가 끊겨 **사진이 빠진 컷**이 있으면 어느 세트의 어느 View가 왜 빠졌는지 목록.
3. **시간대별**: 시(0~23)마다 세트 수, 이미지 수, 용량, QR 인식 / 미인식 / 인식률.
4. **QR 인식 결과**
   - 세트 중 인식 / 미인식 / **인식률**, 미인식 중 "위치만 찾고 못 읽음"과 "아예 못 찾음", 서로 다른 신발(QR 값) 종류 수
   - **값을 읽은 곳**(저장된 사진 `capture`, 실시간 `live`, 캡처 직후 `live_late`, 확대 `capture_zoom`)
   - **어느 카메라에서 읽었나**(left / right 등)
   - **읽은 방법**(`cv` 기본, `rect+zxing` 등 추가 시도)
   - **QR 크기별**(사진에서 가장 큰 QR의 한 변 px: 읽음 / 위치만 찾고 못 읽음)
   - **라벨 상태** 개수
   - **신발(QR 값)별 세트**: 값, 세트 수, 첫/마지막 촬영, 출처
   - **QR 값이 없는 세트 목록**: 촬영 시각, 세트 id, 위치만 찾은 QR 크기
5. **압축 파일 안의 구성**과 파일 개수. zip 안의 경로가 `captures/` 기준이라 풀어서 그대로 합칠 수 있습니다.

숫자는 QR 화면의 일별 표와 같은 기준(세트 = 신발 한 번 지나감)입니다.

## 복원
```bash
unzip backups/capture_2026-10-15.zip -d captures/    # 풀면 .sets/, top/, back/ ... 이 제자리에 들어갑니다
```
앱은 2분 안에 복원된 세트를 화면에 다시 보여 줍니다.

## 주의
- 지우는 것은 **영구 삭제**입니다(휴지통으로 가지 않음). 처음에는 `--dry-run`으로 계획을 보고, 다음에 `--keep`으로 zip이 잘 만들어지는지 확인한 뒤 지우는 실행을 하세요.
- zip을 다른 디스크나 NAS로 옮겨 두는 것은 이 스크립트가 하지 않습니다.
